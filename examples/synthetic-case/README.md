# Синтетический кейс «Удержание абонентов»

Это основной демонстрационный трек дисциплины. Он создан авторами репозитория, полностью генерируется кодом и не содержит персональных данных. Два UCI-набора остаются доступными как альтернативные проектные треки.

## 1. Прикладная постановка

Сервис подписки раз в месяц решает, каким абонентам предложить консультацию или персональные условия перед очередным продлением. Команда удержания может связаться только с 15% клиентской базы.

**Пользователь результата:** руководитель команды удержания.

**Решение:** составить приоритетный список абонентов для контакта на дату снимка данных.

**Целевая переменная:** `churn_30d` — прекратил ли абонент пользоваться подпиской в следующие 30 дней.

**Единица анализа:** состояние одного абонента на конкретную `snapshot_date`.

Модель нужна не ради максимальной метрики. Аналитик должен показать, какие данные доступны в момент решения, как меняется риск во времени, какие ошибки особенно дороги и насколько полезен список из верхних 15% риска.

## 2. Учебные особенности данных

Генератор намеренно создаёт:

- числовые и категориальные признаки;
- восемь ежемесячных снимков и повторные наблюдения одних клиентов;
- пропуски в канале привлечения, использовании и удовлетворённости;
- точные дубликаты;
- выбросы в использовании и абонентской плате;
- несбалансированный класс оттока;
- временной дрейф риска;
- `leaked_churn_score`, почти напрямую кодирующий будущую цель;
- `retention_offer_result_14d`, который появляется через 14 дней после решения;
- возможность временного разбиения и разбиения по `customer_id`.

Поля `leaked_churn_score` и `retention_offer_result_14d` нельзя использовать при обучении модели. Их наличие — часть задания по распознаванию утечки, а не приглашение получить высокую метрику.

## 3. Состав полей

| Поле | Тип | Смысл и доступность |
|---|---|---|
| `row_id` | строка | идентификатор снимка; у точных дубликатов повторяется |
| `customer_id` | строка | искусственный идентификатор клиента и ключ для группового разбиения |
| `snapshot_date` | дата | момент принятия решения |
| `region`, `plan_type`, `acquisition_channel`, `autopay` | категории | характеристики, доступные на дату снимка |
| `tenure_months`, `monthly_fee` | числа | стаж и текущая абонентская плата |
| `usage_hours_30d`, `usage_change_90d` | числа | уровень и динамика использования |
| `support_tickets_90d`, `late_payments_6m` | целые числа | обращения и задержки оплаты |
| `satisfaction_score`, `days_since_last_login` | числа | оценка удовлетворённости и давность входа |
| `network_incidents_30d` | целое число | зарегистрированные инциденты до даты решения |
| `leaked_churn_score` | число | специально созданная утечка из будущей цели; недоступен |
| `retention_offer_result_14d` | категория | результат контакта через 14 дней; постфактум-признак |
| `churn_30d` | 0/1 | будущий целевой исход |

Машиночитаемое описание создаётся в [`data/schema.json`](data/schema.json).

## 6. Воспроизводимость

Основной набор создаётся с seed `20260728`, 1200 клиентами и восемью месяцами наблюдений. Параметры, контрольная сумма файла, число строк и доля цели записываются в [`generation-manifest.json`](data/generation-manifest.json).

Повторная генерация с теми же параметрами должна давать одинаковые значения. Для нового варианта параметры передаются явно:

```bash
python examples/synthetic-case/generate_data.py \
  --output variant.csv \
  --seed 31001 \
  --n-customers 900 \
  --months 8 \
  --missing-rate 0.08 \
  --churn-logit-shift 0.2
```

Пакетная генерация трёх вариантов:

```bash
python examples/synthetic-case/generate_variants.py --count 3 --output-dir variants
```

Каждый вариант получает отдельный seed и один из трёх профилей сложности. Файл `variants.json` сохраняет параметры и контрольные суммы.

## 7. Правила разбиения и утечки

Эталонный протокол использует первые шесть месяцев для обучения и последние два для проверки. Все строки контрольного периода строго позже обучающего периода. Случайное разбиение отдельных строк для основной оценки не применяется.

Для отдельного методического эксперимента допустимо групповое разбиение по `customer_id`, если преподаватель хочет проверить перенос на новых клиентов. В этом случае один клиент не должен встречаться в обеих частях.

Перед разбиением удаляются только точные дубликаты. Параметры заполнения, масштабирования и кодирования обучаются исключительно на train. Безопасный список признаков находится в [`src/data_preparation.py`](src/data_preparation.py).

## 8. Эталонный baseline и диапазоны

Baseline преподавателя — логистическая регрессия с медианным заполнением числовых полей, заполнением категорий, масштабированием и one-hot-кодированием. Он исключает оба недоступных поля и использует временную проверку.

Ожидаемые диагностические диапазоны:

| Метрика | Диапазон |
|---|---:|
| ROC-AUC | 0,68–0,90 |
| Average Precision | 0,22–0,62 |
| F1 при пороге 0,50 | 0,25–0,55 |
| Precision среди верхних 15% риска | 0,28–0,70 |
| Recall среди верхних 15% риска | 0,25–0,70 |

Это диапазоны для обнаружения поломанной генерации или pipeline, а не нормативы оценки. Варианты данных могут давать другие значения. Результат основного запуска сохраняется в [`baseline-metrics.json`](teacher/reference-output/baseline-metrics.json), одна строка эксперимента — в [`experiment-log.csv`](teacher/reference-output/experiment-log.csv).

## 9. Связь с дисциплиной

| Этап | Работа на кейсе | КИМ и индикаторы |
|---|---|---|
| Постановка | определить решение команды удержания, единицу анализа, горизонт и цену ошибок | [КИМ-1](../../M1-task-formulation/kim-01-project-brief.md), `LC-1.1` |
| Понимание данных | описать генерацию, временную структуру, пропуски, дубликаты, выбросы и дисбаланс | [КИМ-2](../../M2-data-understanding/kim-02-eda.md), `BD-1.2` |
| Подготовка | исключить недоступные поля, удалить дубликаты, обработать пропуски и собрать pipeline | [КИМ-3](../../M3-data-preparation/kim-03-data-preparation.md), `BD-1.3`, `BD-1.5`, `ML-2.2` |
| Моделирование | сравнить наивное правило, логистическую регрессию и альтернативу | [КИМ-4](../../M4-modeling/kim-04-modeling.md), `ML-2.1`, `ML-2.2` |
| Оценка | обосновать временную проверку, PR-метрики, top-15% и анализ ошибок | [КИМ-5](../../M5-evaluation/kim-05-validation.md), `ML-2.3` |
| Продукт | подготовить приоритетный список, ограничения, инструкцию запуска и рекомендацию | [КИМ-6](../../M6-analytical-product/kim-06-analytical-report.md), все целевые индикаторы |

Студент может использовать кейс как общий лабораторный пример или как основу собственного проекта. Эталонный baseline предназначен для преподавателя и рецензента. В открытом репозитории он технически доступен, поэтому самостоятельность проверяется по истории решений, варианту данных и ответам на защите, а не по сокрытию файла.
