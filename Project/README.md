# Сквозной аналитический проект

Проект — интегральное задание дисциплины. Каждый модуль добавляет проверяемый артефакт к одному кейсу, а модуль 6 собирает их в итоговый аналитический продукт.

## 1. Сценарий

Команда выбирает один из двух рекомендуемых треков либо согласует собственный набор данных:

1. **Bank Marketing:** классификация отклика на предложение банковского продукта. Особое внимание — моменту доступности признаков, дисбалансу и признаку `duration` как потенциальной утечке для решения до звонка.
2. **Bike Sharing:** прогноз спроса на аренду велосипедов. Особое внимание — временному разбиению, сезонности и признакам `casual`/`registered`, которые в сумме образуют целевую переменную `cnt`.

Источники и лицензии приведены в [каталоге датасетов](../resources/datasets/README.md).

## 4. Командная работа

- Размер команды: 2–3 человека.
- Каждый участник делает содержательный вклад хотя бы в два этапа.
- Вклад подтверждается коммитами или `contribution-log.md`.
- Командные артефакты оцениваются одинаково, защита — индивидуально.
- Участник должен объяснить любой ключевой выбор проекта, даже если код писал другой член команды.

## 5. Критические условия

До защиты должны быть устранены:

- утечка целевой информации;
- несоответствие схемы валидации реальному сценарию применения;
- невозможность воспроизвести основные результаты;
- отсутствие лицензии или ссылки на источник данных;
- скрытое использование генеративного ИИ;
- причинные утверждения, не поддержанные дизайном исследования.

## 6. Изменение постановки

CRISP-DM рассматривается как итеративный процесс. После EDA и оценки моделей разрешено изменить исходную постановку, если команда:

1. сохраняет предыдущую версию паспорта;
2. документирует новые свидетельства;
3. объясняет влияние изменения на критерии успешности и данные;
4. согласует существенное изменение с преподавателем.
