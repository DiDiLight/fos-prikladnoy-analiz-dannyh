# Методические указания

| Раздел | Для кого | Содержание |
|---|---|---|
| [students](students/README.md) | обучающиеся | выполнение, сдача, воспроизводимость и защита КИМ |
| [teachers-assessment](teachers-assessment/README.md) | преподаватели | проверка работ, фиксация индикаторов, защита и апелляции |
| [teachers-resources](teachers-resources/README.md) | преподаватели | подбор данных, кейсов, библиотек и внешних материалов |

Основной принцип прост: преподаватель оценивает конкретный результат и объяснение студента, а не количество кода, библиотек или сложность выбранной модели.

Общий пример для занятий — [авторский синтетический кейс удержания абонентов](../examples/synthetic-case/README.md). В нём есть стартовый ноутбук, преподавательский baseline, генератор вариантов и автоматические тесты. В открытом репозитории baseline доступен, поэтому преподаватель использует варианты данных и индивидуальные вопросы для проверки самостоятельности.

Вспомогательный контур включает входной [КИМ-0](../Entry/kim-00-diagnostic.md), [мини-коллоквиум](../resources/test-banks/mini-colloquium.md) и [банк практических ситуаций](../resources/test-banks/question-bank.md). Эти формы дают раннюю обратную связь и помогают не переносить ошибку в следующий этап, но не приносят баллов. Основным доказательством освоения остаётся артефакт сквозного проекта, проверенный по рубрике и подтверждённый на защите.
