# Методические указания преподавателям по оцениванию

## 1. Принцип оценки

Оценка относится к артефакту и наблюдаемому действию студента. Количество библиотек, строк кода или сложность модели сами по себе не повышают балл.

## 2. Работа с рубрикой

- До выдачи задания разберите со студентами критерии и критические ошибки.
- Начисляйте балл по ближайшему полностью подтверждённому дескриптору.
- Для каждого снижения указывайте критерий и наблюдаемое свидетельство.
- Не начисляйте один и тот же балл дважды за один артефакт.
- Если работа между уровнями, используйте более низкий подтверждённый уровень и конкретную рекомендацию для повышения.

## 3. Калибровка

Перед первым оцениванием два преподавателя независимо проверяют 2–3 работы разных уровней, сравнивают баллы и согласуют трактовку критериев. При расхождении более 10% повторяется совместная проверка.

## 4. Критические ошибки

Утечка целевой информации, некорректная валидация, невоспроизводимость и нарушение правил данных возвращаются на исправление. Остальные сильные стороны работы сохраняют баллы, если локальный акт не требует иного.

## 5. Генеративный ИИ и самостоятельность

Наличие ИИ-помощи не является нарушением при соблюдении правил. Признаками недостигнутого результата являются неспособность объяснить код, воспроизвести вывод, изменить решение или назвать ограничения. Самостоятельность проверяется вопросами и небольшим изменением на защите.

## 6. Обратная связь и апелляция

Комментарий должен содержать: критерий, наблюдение, влияние на результат и конкретный следующий шаг. Апелляция рассматривается по той же рубрике другим преподавателем или комиссией.
