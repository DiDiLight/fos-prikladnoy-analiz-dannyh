# Паспорт фонда оценочных средств

## 1. Общие сведения

| Параметр | Значение |
|---|---|
| Дисциплина | Прикладной анализ данных |
| Период обучения | один семестр |
| Текущий контроль | шесть контрольных точек сквозного проекта |
| Формирующий контроль | КИМ-0 и мини-коллоквиум без начисления баллов |
| Промежуточная аттестация | дифференцированный зачёт |
| Форма аттестации | представление итогового проекта и индивидуальная защита |
| Максимальный балл | 100 |
| Проект | индивидуально или в паре |
| Защита | индивидуальная для каждого студента |

ФОС проверяет не знание синтаксиса Python само по себе, а способность пройти полный цикл анализа данных и объяснить принятые решения.

Паспорт фиксирует состав оценочных средств, карту баллов и пороги. Единый построчный обзор связи содержания, индикаторов, артефактов, КИМ, рубрик и ресурсов приведён в [модели измерения](measurement-model.md).

### Вспомогательные формы

| Форма | Проверяемые индикаторы | Наблюдаемый результат | Как используется | Вклад в 100 баллов |
|---|---|---|---|---:|
| [КИМ-0. Входная диагностика](../Entry/kim-00-diagnostic.md) | `ВК-1.1`–`ВК-4.2` | ответы, диагностический ноутбук и уровень по каждому входному индикатору | адресное повторение и повторная проверка недостигнутого действия | 0 |
| [Мини-коллоквиум](../resources/test-banks/mini-colloquium.md) | `BD-1.5`, `ML-2.2`, `ML-2.3` | шесть обоснованных решений по утечке, pipeline, валидации и метрикам | обратная связь и готовность к принятию протокола КИМ-5 | 0 |
| [Банк вопросов](../resources/test-banks/question-bank.md) | все семь целевых индикаторов | короткий ответ на практическую ситуацию | подбор вариантов для обсуждения и повторной беседы | 0 |

Вспомогательные формы не создают КИМ-7 и не добавляют контрольных баллов. Они помогают обнаружить ошибочное решение до зависимого этапа. Основным доказательством освоения целевого индикатора остаётся проектный артефакт, оценённый по рубрике, затем итоговый продукт и ответ на защите.

Число в ячейке показывает, сколько баллов конкретного оценочного средства относится к индикатору.

|---|---:|---:|---:|---:|---:|---:|---:|---:|
| КИМ-1 | 10 | 0 | 0 | 0 | 0 | 0 | 0 | 10 |
| КИМ-2 | 0 | 15 | 0 | 0 | 0 | 0 | 0 | 15 |

| КИМ-5 | 0 | 0 | 0 | 0 | 0 | 0 | 15 | 15 |
| КИМ-6 | 2 | 2 | 2 | 2 | 2 | 2 | 3 | 15 |

Каждый индикатор проверяется не один раз: сначала в профильном задании, затем в итоговом продукте и на защите. Поэтому единичная случайная ошибка не определяет результат за весь курс, но студент обязан подтвердить каждую часть работы.

Кроме балльного порога, в итоговом продукте должно быть свидетельство по индикатору, а на защите студент должен объяснить соответствующее решение. Если устный ответ не подтверждает авторство или понимание, преподаватель назначает дополнительный вопрос либо повторную защиту только по этому индикатору.

## 5. Как устроено каждое оценочное средство

Каждый КИМ содержит одинаковый набор обязательных частей:

1. назначение;
2. коды компетенций и индикаторов;
3. формулировку задания;
4. условия и срок выполнения;
5. точный состав сдаваемых файлов;
6. рубрику с распределением баллов по индикаторам;
7. правила использования источников и ИИ-инструментов;
8. перечень критических ошибок и самопроверку.

Преподаватель выдаёт студентам КИМ вместе с рубрикой. Менять критерии после сдачи работы нельзя.

## 6. Порядок проведения текущего контроля

1. На лекции разбираются понятия и основания выбора метода.
2. На лабораторной группа выполняет аналогичное действие на общем учебном наборе.
3. Студент или пара переносит действие в собственный проект.
4. В срок сдаётся ссылка на конкретный commit.
5. Преподаватель оценивает работу по рубрике и указывает, какой индикатор подтверждён, а какой требует исправления.
6. Критическая ошибка исправляется до перехода к зависимому этапу. Например, моделирование нельзя оценивать на данных с неустранённой утечкой.

## 7. Работа в паре

Общий артефакт пары получает общий балл за содержательную часть. При этом:

- в `contribution-log.md` указано, кто отвечал за конкретные решения и файлы;
- каждый участник вносит содержательный вклад как минимум в два этапа;
- история Git или журнал вклада подтверждает работу участников;
- балл за защиту выставляется отдельно;
- студент должен понимать весь проект, а не только собственный файл.

Если вклад участника не подтверждён, преподаватель оценивает его часть индивидуально по тем же критериям.

## 8. Критические ошибки

Работа возвращается на исправление независимо от набранной суммы, если:

- признаки содержат неустранённую целевую или временную утечку;
- схема разбиения даёт объектам одной группы или будущим наблюдениям попасть в обучение;
- основные результаты нельзя повторить по инструкции;
- источник данных или право использования не указаны;
- численные выводы в отчёте не совпадают с кодом;
- студент выдаёт корреляцию за причинную связь без подходящего дизайна;
- происхождение существенного внешнего кода или текста скрыто.

После исправления сохраняются баллы по критериям, которые не связаны с ошибкой.

## 9. Фиксация результата

Для каждого студента преподаватель хранит:

- ссылку на commit каждой контрольной точки;
- заполненную рубрику;
- краткий комментарий по недостигнутым индикаторам;
- итоговую таблицу баллов по индикаторам;
- [протокол защиты](../Exam/defense-protocol.md).

Итоговая шкала, условия положительной оценки и порядок пересдачи приведены в [системе оценивания](assessment-system.md).
