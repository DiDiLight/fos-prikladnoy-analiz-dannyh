# Модель компетенций дисциплины

В документах курса используются два набора кодов.

1. `ВК` — входные компетенции. Это внутренние обозначения курса, созданные для учебного проекта. Они не заменяют компетенции образовательной программы и нужны только для входной диагностики.
2. `LC-1`, `BD-1`, `ML-2` — целевые компетенции КРМ 3.0. По ним строятся ФОС, проект и дифференцированный зачёт.

Такое разделение не смешивает уже освоенные умения с результатами, которые формируются в дисциплине.

## 1. Уровни

| Уровень | Как проявляется |
|---|---|
| Б — базовый | студент выполняет знакомое действие по известному способу и может объяснить полученный результат |
| С — средний | студент выбирает способ под задачу, обосновывает решение, проверяет качество и называет ограничения |
| П — продвинутый | студент устойчиво переносит способ в новые и более сложные условия, сопоставляет альтернативы и отвечает за последствия решения |

Для входных компетенций требуется уровень Б. Для целевых индикаторов дисциплины — уровень С.

## 4. Почему `BD-1` формируется на уровне С

В КРМ 3.0 для роли Data Analyst по `BD-1` рекомендован уровень П. Дисциплина «Прикладной анализ данных» формирует **промежуточный уровень С**: студент проходит полный цикл одного проекта и самостоятельно обосновывает исследование, очистку и отбор признаков в пределах выбранного кейса.

Курс занимает 3 ЗЕТ, или 108 часов. За это время нельзя получить несколько независимых свидетельств того, что студент устойчиво переносит способы работы с данными между незнакомыми областями, противоречивыми требованиями и разными источниками. Поэтому заявлять уровень П по результатам одной дисциплины было бы методически необоснованно.

Доведение `BD-1` до уровня П может продолжаться в последующих дисциплинах, проектном практикуме, практике, НИРС или выпускной работе. Это варианты построения образовательной программы, а не обязательные элементы курса. Компетенции, артефакты и формы контроля для такой связки приведены в [траектории роли Data Analyst](role-trajectory.md).

## 5. Когда индикатор считается освоенным

Индикатор считается подтверждённым, если выполнены три условия:

1. студент набрал не менее половины баллов, отведённых этому индикатору;
2. в итоговом продукте есть проверяемое свидетельство: текст, расчёт, график, код или решение;
3. на защите студент может объяснить соответствующее решение без внешней подсказки.

Компетенция считается освоенной, когда подтверждены все входящие в неё индикаторы. Полная карта баллов и заданий приведена в [паспорте ФОС](fos.md).
