# Инструкция внешней команде-рецензенту

## Цель проверки

Проверить согласованность цепочки:

> роль → компетенция → индикатор → предметный дескриптор → КИМ → рубрика → итоговый балл.

## Технический запуск из чистого окружения

Используется Python 3.12 и единый [`requirements-lock.txt`](../requirements-lock.txt). Для PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --disable-pip-version-check -r requirements-lock.txt
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe scripts\validate_repository.py
.\.venv\Scripts\python.exe scripts\smoke_test.py
.\.venv\Scripts\python.exe -m unittest discover -s examples\synthetic-case\tests -v
```

Для обычной командной строки Windows:

```bat
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install --disable-pip-version-check -r requirements-lock.txt
.venv\Scripts\python.exe -m pip check
.venv\Scripts\python.exe scripts\validate_repository.py
.venv\Scripts\python.exe scripts\smoke_test.py
.venv\Scripts\python.exe -m unittest discover -s examples\synthetic-case\tests -v
```

Валидатор проверяет ссылки вместе с якорями, обязательные файлы, шаблонные маркеры, расчёт каждой рубрики, соответствие КИМ карте ФОС и пороги индикаторов. Отдельно он сверяет ключевые положения КРМ и опубликованных DOCX/PPTX с Markdown. Smoke-test работает во временной папке: создаёт небольшой набор, строит логистический baseline и завершает работу с ошибкой, если недоступный признак попал в эталонный пайплайн.

## Быстрый сценарий

1. Выполните технический запуск из раздела выше и сравните его результат с GitHub Actions.
2. Прочитайте [статус комплекта](publication-status.md) и [РПД](rpd.md), затем проверьте достижимость результатов за 108 часов.
3. Сверьте входные и целевые индикаторы в [модели компетенций](competency-model.md).
4. Проверьте по [траектории роли](role-trajectory.md), что уровень С по `BD-1` не выдан за рекомендованный для Data Analyst уровень П, а последующие элементы описаны как возможные.
5. Откройте [единую модель измерения](measurement-model.md) и проследите две-три строки от тематического содержания до артефакта, КИМ, рубрики и балла.
6. Проверьте карту покрытия в [паспорте ФОС](fos.md): суммы модели измерения по КИМ и индикаторам должны совпадать с паспортом, общий итог — 100.
7. Проверьте синхронизацию учебного и проектного контуров по [семестровому плану](semester-guide.md).
8. Выберите по одному КИМ из модулей 1–5 и сопоставьте каждую строку рубрики с индикатором.
9. Проверьте [формирующий контур](../resources/test-banks/README.md): вопросы должны требовать решения, покрывать индикаторы и не добавлять баллы сверх 100.
10. Просмотрите вывод smoke-test и тестов [авторского синтетического кейса](../examples/synthetic-case/README.md): baseline должен работать без `leaked_churn_score` и `retention_offer_result_14d`.
11. Проверьте итоговый [проект](../Project/README.md), материалы студента и индивидуальность [защиты](../Exam/README.md).
12. Откройте [офисные приложения](attachments/README.md) и убедитесь, что название, семестр, индикаторы, баллы и уровень `BD-1` совпадают с Markdown.
13. Зафиксируйте замечания в Issue либо Pull Request с указанием файла и критерия.

## Вопросы рецензенту

- Можно ли по формулировке КИМ однозначно понять, что сдаёт студент?
- Позволяет ли рубрика различить базовое выполнение и самостоятельный обоснованный выбор?
- Есть ли результат обучения, который не подтверждается артефактом?
- Восстанавливается ли по одной строке модели цепочка от элемента дисциплины до начисленного балла?
- Можно ли по карте ФОС восстановить балл каждого индикатора?
- Понятно ли, что КИМ-0 и мини-коллоквиум дают обратную связь, но не заменяют проект и не меняют 100 баллов?
- Требует ли каждый вопрос банка выбора или обоснования действия вместо воспроизведения синтаксиса?
- Не оценивается ли один и тот же результат дважды без добавления нового уровня сложности?
- Достаточно ли отделён результат дисциплины на уровне С от возможного подтверждения уровня П в дальнейшей траектории?
- Достаточны ли данные и ресурсы для выполнения задания?
- Воспроизводится ли авторский набор и остаётся ли baseline в заявленном диапазоне без недоступных признаков?
- Понятно ли, что студент обязан раскрыть и объяснить при использовании внешних инструментов?
- Можно ли воспроизвести итоговый проект из чистого окружения?
